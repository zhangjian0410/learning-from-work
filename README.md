# 从工作中学习

`learning-from-work` 帮你在一次工作结束后，找出下次值得保留的做法、仍未解决的问题，以及现有流程需要调整的具体位置。每个判断都回到你提供的材料；没有新经验，也可以得出无需新增的结论。

适合活动收尾、运营周期复盘、研究和交付总结，也适合研发任务。这里的 work 指已完成的工作，不特指某个产品的 Work 模式。无需搭建 Personal AI OS、学习编程或使用 Obsidian。聊天记录、会议纪要、交付物、现行清单都可以成为起点。

## 获取同一版本

本仓库是唯一维护源，维护者和同事使用同一份 Skill。个人的材料位置、允许读取的范围、调度时间和复盘产物留在各自工作区。更新这里的能力，不需要同步另一个个人版。

当前版本为 [v0.2.0](https://github.com/zhangjian0410/learning-from-work/releases/tag/v0.2.0)，使用 `learning-from-work` 名称，安装时保留整个同名文件夹及相对引用。同事协作时采用同一已核验 revision 或发布包，记录版本和本地改动；升级后保留原任务记录。

更名前的 [v0.1.1 历史发布](https://github.com/zhangjian0410/distilling-task-learning/releases/tag/v0.1.1) 仍使用 `distilling-task-learning-v0.1.1.zip` 和旧技能名；它不是本次更名后的版本。v0.2.0 同步更名，并明确轻量建议与实际应用的不同前置条件，补充固定跨会话验收材料。旧 tag、历史回执与候选 ID 保留原身份。迁移安装时撤下旧发现入口，只保留新名称指向同一维护源，避免同时发现两份技能。

## 开始使用

准备两类材料：本次工作的结果与关键过程，以及这项工作目前遵循的清单、制度或方法。材料不齐也能开始，AI 应说明哪些判断还缺依据。只提供本次相关且允许处理的内容。

- **支持 SKILL.md 的工具**：按该工具的技能安装方式添加整个 `learning-from-work` 目录，保留 `references/` 等相对路径。随后调用此技能并提供任务材料。
- **其他能读取文本或附件的工具**：提供 [SKILL.md](SKILL.md)，请工具先读取正文，并按正文要求提供或读取链接材料。若工具不能访问链接，就补充对应文件。不同产品的文件读取和执行方式不同，这不保证任意聊天产品都会自动安装或执行技能。

不需要先知道技能源码放在哪里。默认在当前对话交付结果；需要保存时，沿用你的任务目录、共享盘或工作区约定。个人材料和实际复盘记录留在你的工作区，分享技能包时不要一并带入。

## 三种请求

**一次任务收尾**

> 请用 learning-from-work 复盘这次客户活动。我提供发送记录、问题单、总结和现行活动清单。列出已有要求遗漏执行的地方、尚未解决的问题，以及值得提出的局部修改。先在对话给我结果和具体差异。

[客户活动案例](examples/customer-event-closeout.md) 包含可直接试用的合成材料。

**一个周期的复盘**

> 请复盘这三周的运营任务，并读取已有候选记录。重复材料只算一次；口径更正保留前后版本。沿用原候选 ID，说明这次增加了什么证据，并提出下一项核验。

[运营周期案例](examples/operations-period-review.md) 演示重叠输入、更正与候选延续。需要每周运行时，由你已有的调度器提供约定范围内的输入；本技能不负责建立定时任务。周期复盘的授权不自动包含正式规则修改。

**检查经验是否用起来了**

> 请对照上次候选、实际修改记录和这次独立任务的执行证据，判断新检查项是否得到复用。区分提出建议、完成修改、后续采用和效果验证。

[研发案例](examples/development-reuse.md) 演示同一故障的重试如何计数，以及什么证据支持后续复用。

## 你会得到什么

结果包括值得保留的结论、来源、适用范围、开放问题和下一步。有修改价值时，给出针对现有清单或方法的具体差异，供你审阅；请求复盘本身不等于请求修改正式规则。

同一事件出现在三份文件里仍是一个事件。同一任务重试两次仍是一个任务。已有规则覆盖的要求会标明出处；新增建议会说明边界。提出候选、应用修改、后续复用与效果改善，各自需要对应证据。

## 可选：连接个人记忆

已有个人 Context 或项目笔记时，可按[组合说明](references/context-integration.md)提供来源、现行做法和已有授权，让整理结果进入合适的记忆位置。此集成不增加使用前提，也不改变业务审批合同。

## 能力与验证范围

本包交付可移植的文本 Skill，不附带采集器、调度器或恢复引擎。实际读取、保存和执行能力由宿主提供。下表说明如何区分支持方式与验收，不能把文件存在或静态校验当作运行成功。

| 方式 | 使用前提 | 要证明什么 | 本包声明 |
|---|---|---|---|
| 手动文本/附件 | 提供正文及本次需要的引用 | 实际读到材料并完成有来源的复盘 | 支持此文本接口；具体模型行为须实测 |
| 显式文件调用 | 宿主能读取指定路径 | 实际读取 Skill、必要引用和获准材料 | [固定验收](acceptance/README.md)可重跑；结果按版本和宿主记录 |
| 原生技能发现 | 按宿主方式安装整个目录 | 新会话发现正确名称并读取当前正文 | 未附本版运行回执时为 NOT_RUN；显式路径读取不能替代 |
| 宿主周期执行 | 已有调度、范围授权和持久状态 | 真实触发、断点恢复、并发及回退行为 | 由宿主单独验收；本包未认证任何调度实现 |
| 后续真实复用 | 独立真实任务和采用证据 | 改进被采用且出现预期行为 | 合成测试不支持此结论；未取证为 UNKNOWN |

上面的三份案例用于理解行为；[固定跨会话验收](acceptance/README.md)把原始任务与检查者断言分开，可验证保存、原样重跑、更正和未知目标的处理。全部为合成材料，不代表真实业务成效或通用兼容认证。静态检查、显式路径、原生发现、调度和真实复用分别记录，未运行不写 PASS，也不推算节省时间、费用或准确率。
